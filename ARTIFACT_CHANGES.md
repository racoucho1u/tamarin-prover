# Changes made to the artifact

This file lists the functional changes made to the repository. Changes that only improve the clarity, language or typos of `Readme.md` are not listed. Nothing has been committed.

## 1. Tactic generation no longer modifies the input theory files

**Files:** `tamarin-prover/tacticGeneration.py`, `artifacts/tacticGenerationBenchmark/tacticGenerationMerged.py`

**Problem:** to use a generated tactic, the scripts added `#include "tacticGeneration/generatedTactics/..."` directly to the input `.spthy` file.

- Running the README example therefore modified `SourceOfUniqueness.spthy`, including the reviewer's copy on the host through the Docker bind mount.
- In the tactic benchmark, the edited files are the shared ones in `artifacts/files_to_benchmark/all/`. These are also used by the strategies benchmark.
- Tamarin resolves an `#include` relative to the directory of the including theory, not the current directory. In the benchmark, the include therefore pointed to a file that does not exist.

**Fix:**

- New function `working_copy()`. Each proof now runs on a private copy of the theory in `tacticGeneration/theories/<strategy>_<lemma>_<file>.spthy`, so the original file is never modified. The copy is refreshed at the first attempt of each run.
- `add_tactic_to_file()` was rewritten:
  - The include path is computed relative to the copy's directory, e.g. `../generatedTactics/...`.
  - Previously inserted tactic includes are removed before the new one is added, so the function can be called repeatedly.
  - The include goes right before the final `end` line. The old test `'end' in line` also matched words such as "append".
- At the first attempt of a run, the tactic file in `tacticGeneration/generatedTactics/` is overwritten instead of appended to. Otherwise, rerunning the script would add tactics with duplicate names (`<lemma>_0`, ...).
- Result files, tactic names and the lines printed to `scriptResult` keep the original theory path, so `resultsTacticGen.py` parses them as before.

**Tested:**

- The README example (`tacticGeneration.py ... --strategy=Proba --timeout=1`) passes twice in a row. `SourceOfUniqueness.spthy` is unchanged and the tactic file holds `uniqueness_0` and `uniqueness_1` exactly once.
- The reduced tactic benchmark ran with timeouts shortened to 10 s, and `resultsTacticGen.py` parsed its output.

## 2. Wrong server path in the tactic generation benchmark

**File:** `artifacts/tacticGenerationBenchmark/tacticGenerationMerged.py`

**Problem:** tactics were written to `../tacticGenerationBenchmarkServer/tacticGeneration/generatedTactics/...`, a path from the original server that does not exist in the artifact. Writing the tactic raised an exception, which the script caught and recorded as "Error in generation". As a result, no tactic could ever be generated by `tacticGenBench.py`.

**Fix:** tactics are written to `tacticGeneration/generatedTactics/...`, the folder that `tacticGenBench.py` creates. This is the same location as in `tacticGeneration.py`.

## 3. Full-scale strategies recipe: theory paths

**File:** `artifacts/strategiesBenchmark/recipe_strategy_benchmark.json`

**Problem:** all 366 tasks used `files_to_benchmark/...`, but the recipe is run from `artifacts/strategiesBenchmark/`. `batch-tamarin check` failed with "Theory file ... not found".

**Fix:** paths changed to `../files_to_benchmark/...`, as in `recipe_strategy_benchmark_fast.json`. `batch-tamarin check` now generates the 3972 executable tasks.

## 4. Missing theory files for the full tactic generation benchmark

**Files added:** `artifacts/files_to_benchmark/all/{LD07, OTYT06, aletheaDR_ShHh, aletheaDR_ShHh_RF, aletheaDR_SmHh}.spthy`

**Problem:** `tacticGenBench.py` loads every theory from `files_to_benchmark/all/`, but these 5 theories were missing. They are used by 23 of the 215 lemmas in `lemmaToTactic.txt`.

**Fix:** copied unchanged from `files_to_benchmark/jcs19_xor/` (LD07, OTYT06) and `files_to_benchmark/these_ls_chap4/` (the three aletheaDR files). Every lemma in `lemmaToTactic.txt` and `lemmaToTactic_fast.txt` now has its theory in `all/`.

## 5. Analysis scripts appended to existing files

**Files:** `artifacts/strategiesBenchmark/resultsAnalysisScripts/results.py`, `artifacts/tacticGenerationBenchmark/resultsScripts/results.py`

**Problem:** several outputs were opened in append mode and never reset.

- `lemmaToTactic.txt` was written to the current directory. Run from `tacticGenerationBenchmark/`, the analysis appended 215 lines to the shipped input file `lemmaToTactic.txt`.
- `tables.csv` (current directory) and `results/<dir>/table3_timecomp` accumulated results across runs.

**Fix:**

- `lemmaToTactic.txt` and `tables.csv` are now written next to the other outputs, in `results/<dir>/`.
- The three appended files are emptied at the start of each analysis run.
- Missing newline after the header row of `table5_workflow` added.

**Tested:** running both scripts on the full-scale data reproduces the shipped `table2_strategiesresults`, `table3_timecomp`, `table5_combinedResults` and `appendix_strategiesComparedToBaseline`. The generated `lemmaToTactic.txt` contains exactly the 215 lemmas of the shipped list.

## 6. Shipped full-scale tactic tables regenerated

**Files:** `artifacts/tacticGenerationBenchmark/results_fullscale/tables_and_graphs/table3_timecomp`, `.../table5_workflow`

**Problem:** because of the append bug (item 5), `table3_timecomp` contained three accumulated runs (162 lines instead of 54). Only the last block matched the data. `table5_workflow` lacked the newline after its header row.

**Fix:** both files were regenerated with the fixed script from the same data. The new `table3_timecomp` is identical to the last block of the old file, so no numbers changed.

## 7. Hard-coded Docker path in the extraction script

**File:** `artifacts/strategiesBenchmark/resultsAnalysisScripts/analyseResultsBatchTamarinMergedVersion.py`

**Problem:** `metaData.json` was loaded from `/workspace/tamarin-prover/...`, so the script only worked inside Docker.

**Fix:** the path is now relative to the script's own location. The extracted output is identical to the shipped `execution_report_extracted.json` (checked on `server_3`).

## 8. Docker build context

**Files:** `.dockerignore` (new), `Dockerfile` (comment only)

- Added `.dockerignore`, which excludes `.git`, `artifacts`, `.stack-work` and `__pycache__`. Previously the whole repository (about 1.3 GB) was sent to the Docker daemon, although only `tamarin-prover/` is copied into the image. The artifacts are bind-mounted at runtime.
- The usage comment in the `Dockerfile` header now shows the build command used in the README. It previously referred to `local-tamarin.Dockerfile`.

## 9. `.gitignore`

Added patterns for files generated by the experiments, so they are not committed by mistake:

- `__pycache__/` and `*.pyc`
- LibreOffice lock files (`.~lock.*#`)
- `tacticGeneration/` and `exportGoals.spthy`
- the result folders `result_strategiesBenchmark*/` and `results/`
- `data_fast.json` and `data_full.json`

## 10. Stray files removed

Deleted `artifacts/files_to_benchmark/.~lock.recapfile.csv#` (a LibreOffice lock file) and `artifacts/strategiesBenchmark/resultsAnalysisScripts/__pycache__/plot.cpython-312.pyc` (Python bytecode cache). Both were tracked by git; run `git add -A` (or `git rm --cached` on them) when committing.

## 11. README changes reflecting behaviour

Besides the clarity and language fixes, the README was updated to match the code:

- Where the generated tactics, the theory copies and the results of `tacticGeneration.py` are stored.
- The actual options and defaults of `tacticGeneration.py`: the first timeout is 6000 s, not one hour, and it doubles at each attempt. Only `--strategy`, `--heuristic`, `-m` and `--diff` are accepted, not arbitrary Tamarin options.
- `results.py` now writes `lemmaToTactic.txt` into `results/<dir>/`.
- `resultsTacticGen.py` uses the paper's full-scale strategy results by default (option `--inputStrat`).
- The expected maximum running times of the reduced benchmarks (at most 18 h and 3.5 h) and the Docker Desktop resource requirement.
- Correct paths to the shipped results (`results_fullscale`, 5 batches).
- `batch-tamarin` installed from PyPI with the tested version (1.0.0) instead of piwheels.
- The example output file is renamed `exportGoals.txt`, since it is not a theory file.

## Not changed

- **`debian:sid` base image:** it is a moving target, so the build may break in the future. Consider pinning, e.g. `debian:trixie`, which ships Maude 3.4. This was not changed because the image could not be built in the test environment.
- **Root-owned files:** the container runs as root, so files it creates in the bind-mounted repository belong to root on Linux hosts.

## How the changes were tested

Tests were run with the provided binary `tamarin-prover-1.4.1-2468-g300638b4`, Maude 3.2, `batch-tamarin` 1.0.0 and the Python packages of the Dockerfile, with the repository at `/workspace/tamarin-prover`. The Docker image itself could not be built in the test environment, because Docker Hub was not reachable. The full benchmarks were not run.
